Two-tier audit. Tier 1: code cleanliness (bugs, hygiene, robustness, security). Tier 2: content (model methodology, public claims, UI/UX). Findings only. No fixes applied. Every item awaits owner direction.

- Target: this repo (origin `github.com/HaterAndrew/chess-prediction`, deployed at haterandrew.github.io/chess-prediction).

## Top findings

1. **L1**: Mobile tab navigation has been fully dead in production for 67 days. One CSS rule shipped 2026-05-01 (`#panel-predictions{display:flex}` in the mobile media block) outranks the panel-hiding rule by ID specificity; every entry point (taps, Other menu, swipe, hash links) marks the target panel active 17K-37K px below a viewport that never scrolls. Phone users can reach exactly one tab.
2. **J1 + J12**: The site's headline 2026 grade "A" is fabricated in both directions. The 2026 eval fold trains, recalibrates, and grades on the same tournaments (in-sample optimism at long horizons: T-60 MAE 5.9% vs out-of-sample 2025 20.0%), while 5 of 18 graded events are scored against month-frozen registration curves with fresh finals (fabricated pessimism at short horizons: recorded T-1 "errors" of -37% to -65% that the scraper contradicts).
3. **M1**: The deployed public site (line 807) and the public repo still attribute the product to a prior internal-team name (redacted). The scrub replacing it with "HaterAndrew" was drafted locally on 2026-06-11 and never committed; the cron redeploys the unit attribution daily.
4. **H2 + H12**: The roster has been frozen for a month (the missing-export fallback joins onto existing tournaments only and can never add one), and the metadata-fallback card path deletes any roster-pending event the day it starts. Net effect live today: World Open U13 was scraped at 82 entries and has no card at all; 14 more cards will vanish the same way on their start days.
5. **G1 + G2**: Both cron workflows auto-commit to the deploy branch with zero test or lint gate, installing unpinned dependencies fresh each run (no requirements manifest exists). A PyPI release that changes sklearn/scipy behavior alters model output on the next 01:15 UTC run with nothing standing in between.

Cross-cutting: the defect class Audit v1 was built around (one number, two sources, no reconciliation) is alive at every layer: net-vs-gross finals on one page (H13), five contradictory CI-coverage claims on one site (L2/K1), two prediction engines on one page (J14), and truth labels that measure different populations than the ratios trained on them (J13).
